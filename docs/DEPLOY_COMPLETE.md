# Ghost Healer — Complete Deployment Guide

End-to-end: **Brain on Render** + **SDK install** + **verify healing**.

---

## Overview

| Component | Where it runs | What you deploy |
|-----------|---------------|-----------------|
| **AI Brain** | Render (`mcp-server/`) | Docker web service + MongoDB |
| **Python SDK** | User machine / CI | `pip install` (PyPI or git) |
| **TS/JS SDK** | User project | `npm install ghost-healer-ts` |
| **Config** | User project root | `ghost.yaml` + `GHOST_API_KEY` env |

Users **do not** run the Brain locally in production — only install SDK + point at your Render URL.

## Phase 1 — Prerequisites

1. **GitHub repo** pushed: `https://github.com/MansoonMangal/MCP_GHOST_HEALER.git`

3. **Local tools** (for testing before/after deploy):
   - Python 3.10+ and `.venv`
   - Node.js 18+ (for TS SDK build)
   - Git

### Fix GitHub push (if you see `403 denied to dpatil-nr`)

Windows Credential Manager may be using the wrong GitHub user:

1. Open **Credential Manager** → **Windows Credentials**
2. Remove entries for `git:https://github.com`
3. Push again; sign in as **MansoonMangal** (or use a Personal Access Token with `repo` scope)

```powershell

git push origin development
```

## Phase 2 — Deploy Brain on Render

### Step 1: Create Blueprint

1. Render Dashboard → **New** → **Blueprint**
2. Connect repository **MCP_GHOST_HEALER**
3. Render reads root `render.yaml` and creates:
   - Web service: `ghost-healer-brain`
   - Database: `ghost-db` (MongoDB)
4. Click **Apply**

### Step 2: Wait for deploy

- First build runs Docker from `mcp-server/` (5–10 minutes)
- **Health check path**: `/health/ready` (must return 200 without API key)

### Step 3: Copy secrets from Render

Open web service → **Environment**:

| Variable | Source |
|----------|--------|
| `GHOST_API_KEY` | Auto-generated by blueprint |
| `MONGO_URI` | Linked from `ghost-db` |
| Service URL | e.g. `https://ghost-healer-brain.onrender.com` |

### Step 4: Confirm database connected

**Logs** tab should show **one of**:

```text
PostgreSQL connected — using persistent storage (Render Postgres)
```

or (if you use MongoDB Atlas instead):

```text
MongoDB connected — using persistent storage (production mode)
```

Render Blueprint provisions **PostgreSQL** (`postgresql://...`), not MongoDB. The Brain auto-detects the URI scheme.

| Env var | Value |
|---------|--------|
| `DATABASE_URL` | Render Postgres connection string (preferred) |
| `MONGO_URI` | Also works — use only for `mongodb+srv://` (Atlas) |

If you see `Invalid URI scheme: mongodb` or `falling back to JSON files`, ensure you did **not** put a `postgresql://` URL in a variable the app treats as Mongo-only without redeploying the latest code.

### Step 5: Smoke test live Brain

```powershell
$env:GHOST_API_KEY = "<paste from Render>"
python scripts/verify_slo.py --base-url "https://ghost-healer-brain.onrender.com" --api-key $env:GHOST_API_KEY
```

Or in browser (no key needed):

- `https://<your-url>/health`
- `https://<your-url>/health/ready`
- `https://<your-url>/docs`

### Common Render failures

| Symptom | Fix |
|---------|-----|
| Deploy fails / unhealthy | Check logs; ensure `/health/ready` returns 200 (fixed in auth middleware) |
| Port bind error | Use `entrypoint.sh` (Render `PORT` env) — already in repo |
| 401 on heal | Pass `X-API-Key: <GHOST_API_KEY>` from SDK/CI |
| Mongo fallback | Redeploy after `dnspython` + valid `MONGO_URI` |
| Slow first request | Free tier cold start (~30–60s) — normal |

## Phase 3 — Configure client project

In **your test project** (or this repo for demos), create/update **`ghost.yaml`** at repo root:

```yaml
mcp_server:
  url: "https://ghost-healer-brain.onrender.com"
  protocol: "mcp-first"
  confidence_threshold: 0.5
  api_key: ""

healing:
  mode: "runtime"
  cache_enabled: true
  auto_patch: true

reporting:
  output_dir: "reports/ghost"
```

**Never commit the API key in yaml.** Use one-time login or environment:

```powershell
npx ghost-healer login
# or IT / CI:
$env:GHOST_API_KEY = "<team key>"
$env:GHOST_BRAIN_URL = "https://ghost-healer-brain.onrender.com"   # optional override
```

Per-project `.env` editing is **not required** when using `ghost-healer login`.

## Phase 4 — Install and test SDK (local)

### Python

```powershell
cd <your-clone-of-MCP_GHOST_HEALER>
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .

ghost-healer doctor
.\scripts\test_sdk_local.ps1
```

**Doctor** should show Brain `healthy` when Render is up and `GHOST_API_KEY` is set.

**Run demo test** (from subdirectory — config walk-up works):

```powershell
$env:GHOST_API_KEY = "<key>"
cd demo\playwright-python
..\..\.venv\Scripts\pytest test_demo.py -v
```

### TypeScript / JavaScript

```powershell
cd sdk\ts
npm install
npm run build

cd ..\..\demo\playwright-ts
npm install
$env:GHOST_API_KEY = "<key>"
$env:NODE_OPTIONS = "--require <path-to-repo>\sdk\ts\src\auto-activate.js"
npx playwright test
```

Or after publishing to npm:

```bash
npm install ghost-healer-ts-sdk
npx ghost-healer login
npx playwright test
```

### Java

Add framework classes / JAR to test classpath; set:

```bash
export GHOST_BRAIN_URL=https://ghost-healer-brain.onrender.com
export GHOST_API_KEY=<key>
mvn test
```

## Phase 6 — End-user “zero change” checklist

1. Install SDK (`pip install ghost-healer` or `npm install ghost-healer-ts`)
2. Add `ghost.yaml` at project root with Brain URL
3. Set `GHOST_API_KEY` in CI/local env
4. Run existing tests — **no script edits**
5. Review `reports/ghost/` for heal audit trail

| Stack | Activation |
|-------|------------|
| Python + pytest | Auto via pytest plugin |
| Python + plain script | `GHOST_AUTO_ACTIVATE=1` |
| Playwright TS | `postinstall` / `NODE_OPTIONS` auto-activate |
| Java JUnit 5 | Service loader extension |

## What was fixed for Render (in this repo)

1. **`/health/ready` public** — Render health checks no longer get 401 when `GHOST_API_KEY` is set
2. **`entrypoint.sh`** — Binds Gunicorn to Render’s `PORT` correctly
3. **`WEB_CONCURRENCY=1`** — Safer memory use on free tier
4. **`dnspython`** — MongoDB `mongodb+srv://` on Render
5. **Config walk-up + cache anchor** — SDK works from subdirectories

After pulling latest code, **push to GitHub** and **trigger Manual Deploy** on Render (or wait for auto-deploy).
